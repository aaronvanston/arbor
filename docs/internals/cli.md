# Command line

`arbor`, and `arbor mcp` for agents, live in `src-tauri/src/cli/`. They're the app's own program, run through a link
named `arbor` (`~/.local/bin`, added from Settings › App › Command line) or as `Arbor cli …`. A development build's
program is itself called `arbor` and stays the app.

The CLI never opens Arbor's files. It sends each request over a private socket (`<data folder>/cli/arbor.sock`, folder
0700, same-user check) to the running app, which runs the same Tauri command the window would. Locks, guarded writes
and events all apply, and an open window updates by itself.

- `server.rs` answers the socket and `dispatch.rs` runs a request. On the client side: `args.rs`, `client.rs`,
  `render.rs`, `help.rs` (each command's own help, `arbor help <command>`) and `mcp.rs`.
- `commands.rs` is generated by `bun run cli-commands`. `scripts/cli-commands.mjs` holds the commands left out and why,
  and the ones that need confirming. A confirmed command prints its plan and exits 10 without `--yes`
  (`confirm: true` over MCP).
- `bridge.rs` asks the window for what only it works out (limits, caps, routing, Sync's plan, alerts); the window's side
  is `src/services/cliHandlers.ts`.
- `redact.rs` hides secrets in every answer and event. `audit.rs` keeps `cli/activity.jsonl`: method, client and
  outcome, never arguments.
- `management_request` and every claim, reset and redeem call are never reachable.
- Settings the CLI can change sit in the app's `saved-store.json` (`saved_store.rs`); a `savedStore` with
  `place: 'window'` stays in localStorage.

`skill.md` is the agent skill that teaches `arbor`. `arbor skill` prints it, and Settings › App › Command line or
`arbor skill install` write it to this Mac's store and Claude homes through guarded writes
(`usage/machine_health/cli_skill.rs`). Keep it in step when a command changes.
